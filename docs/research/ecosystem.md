## Comparison and decisions

| Workflow | AUTHENTICATOR DESK baseline | Evidence in peers | Product consequence |
|---|---|---|---|
| Keep codes quickly available | Favorites panel and shortcuts | OTPClient clipboard and groups; Authme import UI; FreeOTP token view controller | Preserve quick panel and add active keyboard focus and native verification when touching the interface. |
| Import and rollback safely | Preview; encrypted internal backups; plaintext legacy adapters | Aegis backup manager; Authme issue on new imports; 2FAS multi-batch release notes; OTPClient Linux import modules | Preserve adapters, prioritize future migration fixtures and retain explicit encrypted restore. |
| Install future versions | Manual download only in v0.1.0 | OTP Harbor separates installer service; Tauri provides version-bound signature verification and platform install handoffs | Make a signed stable channel, versioned artifact manifests, visible confirmation, and a documented recovery path. |
| Desktop portability | Windows clipboard backend; portable Rust core | OTPClient uses GTK4; Flauth separates storage; Yubico separates target build paths | Exercise Linux and macOS core. Desktop distribution needs OS-native integration evidence and package security. |
| Web and mobile | Local Windows trust boundary | 2FAuth adds server and API trust; 2FAS browser extension pairs devices; FreeOTP iOS uses Keychain | Preserve offline desktop scope. Evaluate companion surfaces independently, with device, signing and lifecycle gates. |

Keep the established vault/list design, with a bounded update dialog that gives keyboard users a clear first choice, presents release notes on demand, and uses ordinary progress text. The settings page is the update entry point. The default remains manual to preserve offline-first behavior.

The strongest recent signals were OTPClient's settings-schema startup fix, 2FAS Android's multi-batch migration work, Authme's encryption hotfix, Tauri's signed-version support and otplib's package-smoke work. They informed the compatibility and release gates rather than changes to OTP derivation. Recheck active upstream projects monthly through the maintenance workflow. Review full release notes and implementation before major features.
