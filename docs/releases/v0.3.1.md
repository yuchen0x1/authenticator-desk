# AUTHENTICATOR DESK v0.3.1

**Status: prepared candidate, not a published release.** A source version, local build or successful main CI run does not establish signed release availability. Do not use the unsigned local verification builds as official update assets.

## Fixes

- An old Add/Edit save response no longer closes a newer draft after locking, unlocking or recovering the workspace. Native mutations are not replayed.
- Account editing initializes from matching authenticated details, including the latest HOTP counter and metadata, rather than stale list values. HOTP Edit is unavailable while a local counter advance is pending.
- Imported accounts with an empty optional platform/issuer can be edited without inventing a platform name.
- Plain Aegis imports preserve native account names containing colons, such as `alice:prod`; issuer remains a separate field.
- Account cards and the favorites panel use the same CodeView time basis for T0 and expiry. The native UTC clock currently returns zero offset; no network time service was added.
- Release creation explicitly targets the verified tag commit, retaining security, signing, independent installer and downloaded-asset verification gates.

This candidate includes the previously unreleased [0.3.0 reliability changes](v0.3.0.md) and [0.2.1 safety changes](v0.2.1.md). Their source descriptions are not evidence those versions were publicly shipped.

## Compatibility and upgrading

SQLite schema 1, vault encryption, `.authdesk` backup format, application identifier, storage paths and IPC shapes are unchanged. No dependency upgrade or data migration is required by these fixes. Back up first and fully exit all running clients before a future installation. Keep the same installer family (EXE/NSIS or MSI). v0.1.0 requires a manual installation; see [update and recovery](../updating.md).

## Remaining publication and qualification gates

- New exact-source main Security/CI, then authorized tag-triggered signed rebuild and fresh-runner NSIS/MSI installation/reinstallation/uninstallation.
- Verify all seven release assets, minisign signatures, hashes and the stable `update.json` download after publication.
- Genuine prior-version signed update and reopening an existing isolated vault remain unqualified; synthetic signature tests do not substitute for this.
- Local artifacts are Authenticode `NotSigned`; updater/minisign signatures are not a Windows publisher certificate. No publisher certificate was provisioned in this round.
- Whole-repository strict Clippy/rustfmt have existing failures. Rust dependency audit retains six allowed warnings, including target-restricted `glib` unsoundness. Neither is described as fixed or zero-risk.

Encrypted third-party migration formats remain explicitly unsupported. Windows clipboard history/cloud copies and compromised-OS access remain outside the cleanup/vault-at-rest guarantees. No new platform-support claim is made.
