## Release overview

AUTHENTICATOR DESK 0.2.1 fixes release-test discovery, vault/backup lifecycle safety and cross-window privacy. This is a prepared release, not evidence of a published installer or a completed live update.

## Fixes

- Isolate Vitest frontend discovery from the Node.js release-policy tests.
- Enforce the trusted tag/workflow context before signed jobs and signing commands; require dependency/security checks before the release verification pipeline.
- Cryptographically verify the downloaded signed metadata and installer bytes, including the authenticated release version. Serialize stable promotion, reject older stable versions, and verify the public update manifest after publication.
- Reject unknown audit-report shapes and remove the obsolete unscoped dependency-advisory exception. Pin the tested Node/Rust and audit tool versions.
- Honor hidden-code preferences in the main window, favorites panel and display IPC; discard delayed responses after settings or lock changes. Hide expired codes and refuse a visible-copy operation if the code rolled over.
- Preserve successful vault creation across an unlock failure, distinguish recoverable loading errors, and synchronize document language and icon-only navigation labels.
- Limit bulk actions to the reviewed visible selection. Reject blank/invalid security timeouts; disabling a timer requires an explicit separate control.
- Read migration files through a bounded native picker and share Google migration dispatch across paste, files and QR images. Bound the combined batch to 1,000 rows and clear canceled, expired or invalidated previews.
- Initialize vaults before installing the final path, preserve concurrent no-overwrite creation, and enforce the idle deadline on password changes and privileged record access.
- Match backup export and restore limits, show replacement counts, apply restored policies and relock after replacement. Retention deletes only manifest/hash-proven backups owned by this vault; foreign, manual and legacy-unclaimed files remain untouched.
- Prevent stale automatic-backup jobs from overwriting newer configuration or publishing after invalidation; serialize manual backup publication against locking.
- Wipe cipher state and explicitly owned KDF work memory. Reject bare-key global shortcuts and exit cleanly when closing the main window without close-to-tray.
- Run NSIS and MSI installation lifecycles on separate fresh Windows runners so NSIS's remembered directory cannot redirect the MSI smoke test. Refuse pre-existing installations/processes even in CI. Retain the optional pinned-certificate/timestamp Authenticode policy; no publisher signature is claimed without a configured certificate.
- Reserve each canonical vault path with an OS-held sidecar lease before create/unlock. Reject competing writers through password rotation and UI locking; release on owning-service exit. No PID files, stale-lock deletion or new dependencies are used.
- Follow corrected system UTC after forward/backward wall-clock changes and resume, instead of preserving a permanent offset that would keep TOTP codes wrong.
- Keep a restricted Backup/Security recovery surface after successful unlock/settings loading but failed account hydration. Codes and ordinary account pages remain unavailable until a complete successful reload.
- Allow authenticated, explicitly confirmed Replace to recover damaged encrypted account rows without decrypting the outgoing rows. Merge still fails closed on corrupt live accounts; backup authentication and transactional replacement remain mandatory.
- Show both account names and localized failure reasons for invalid import rows, including unsupported digit counts in all four locales.
- Close stale Add/Edit dialog state when settings resynchronization fails, keeping Retry and Lock interactive instead of leaving the recovery surface inert.

## Downloads and upgrading

When v0.2.1 is published, choose the Windows x64 installer matching your existing installation: EXE (NSIS) or MSI. Verify the download, create an encrypted backup and close the application before installing. See the [update and recovery guide](https://github.com/yuchen0x1/authenticator-desk/blob/main/docs/updating.md).

The vault database schema remains at 1 and previous encrypted backups remain readable. New automatic backups carry ownership metadata; do not assume an older application understands every newer backup document. Previous unclaimed automatic backups are preserved and may need manual retention management.

## Qualification boundaries

Local tests, builds and workflow syntax checks do not establish a published signed channel, Authenticode publisher identity, MSI installation acceptance or a genuine prior-version live update. See the latest dated section in `docs/test-report.md` for observed results and remaining checks. Existing public v0.2.0 release assets are not repaired by these local changes; publishing a new verified release remains a separate authorized operation.
